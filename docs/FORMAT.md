# 入力・出力

`examples/battle.json` が実行可能な入力です。型定義は `runner/runner.go` の Input/Fighter/Result、状態型は `runner/replay.go` を参照してください。

## 入力

- `seed`: 整数。乱数の再現用。
- `catalogVersion`: 出力に引き継ぐラベル。マスター選択機能ではない。
- `team`: 前衛・中衛・後衛の順に3体。
- `enemies`: 同じく3体。省略すると既定の守護像3体。
- 各キャラ: `name`, `heroType`, `hp`, `phy`, `int`, `agi`, `actives`（3要素）, `passive`, `attributes`, `faction`。

ヒーローの最大能力に装備2個の能力を加算します。行動候補は装備1のactive、装備2のactive、エディットスキルID。それらを希望順に `actives` へ設定します。未装備は2002（通常攻撃）。ヒーローのパッシブは `passive` に設定します。エディット候補は3001–3008、3101–3130のうちスキルデータに存在するIDです。サンプルは計算確認用に3行動とも通常攻撃です。

`heroType` は型IDです。NFTトークンID・ウォレットアドレスを渡す欄ではありません。無料ノービスは10001–10003、その他の10000以上のヒーロー型は受け付けません。

HPは1–1,000,000、PHY/INT/AGIは1以上、敵のPHY/INT/AGIは999以下という現実装の制約があります。自由な上限を保証しません。200行動で打ち切ります。詳細な制約はrunnerを参照してください。

## 出力

`score` は敵へのダメージスコア、`outcome` は勝敗、`frames` は初期状態と行動ごとの状態です。インデックス0–2は味方前・中・後、3–5は敵前・中・後。`actor`, `targets` もこの位置を参照します。`units` はチャージ、状態異常、能力増減等の状態です。値の意味と計算方法は `runner/replay.go` が正本です。

## スキルデータ

NDJSONはprotobuf JSON形式で、省略された値はprotobufの既定値です。説明文を変更しても計算は変わりません。計算データを変更してから説明を再生成してください。4000000000はrunnerが作る既定NPCスキルの予約ID。カスタムスキルはボス専用で、`runner/custom_skills.go` の型・制約に従います。

## 実行境界

CLIはローカル専用です。ネットワーク公開する場合の認証・入力サイズ・同時実行数・実行時間・費用制限は含みません。未信頼入力を無制限にサーバー実行しないでください。
